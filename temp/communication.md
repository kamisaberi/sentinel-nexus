To connect your existing ecosystem to **Sentinel Nexus (Tier 6)**, we need specific, targeted integration points across the other 5 tiers. 

Importantly, **none of these changes should break the standalone, air-gapped operation of any project**. They act as an **optional telemetry and control uplink** that activates when a Nexus endpoint is configured.

Here is the comprehensive architectural breakdown of the changes required for each project:

---

### 1. `blackbox-sentinel` (Tier 3: Commercial Edge Appliance)
*This is the primary edge daemon and requires the most significant integration work, as it directly reports to Nexus.*

* **New Uplink Module (`src/modules/nexus_client` or `src/core/NexusUplink`):**
  * **gRPC Client Engine:** Embed a background client thread that connects to Nexus (Port `50051`) using standard gRPC stubs generated from `proto/`.
  * **Config Toggle:** Add a `nexus:` block in `configs/sentinel.yaml` (e.g., `enabled: true`, `nexus_host: "10.0.0.1"`, `nexus_port: 50051`, `mtls_enabled: false`). If disabled, Sentinel runs 100% autonomously as it does today.

* **Appliance Enrollment & Registration:**
  * At daemon boot, invoke `blackbox-essential`’s hardware identity subsystem to retrieve the TPM 2.0 quote / DMI UUID.
  * Send `RegistrationRequest` to Nexus `FleetService.RegisterAppliance` and persist the returned `node_id`.

* **Telemetry & Heartbeat Reporter:**
  * Hook into the existing metrics subsystem (CPU, RAM, NPU temperature, and ring buffer fill percentage).
  * Send `HeartbeatRequest` every 5 seconds to Nexus `FleetService.SendHeartbeat`.

* **Selective Active-Learning Stream (Feeder for Forge):**
  * Hook into the inference pipeline (`Tensor Extraction -> Inference`):
  * When `xinfer` scores a flow, check if the output probability falls into the high-uncertainty window ($0.40 \le p \le 0.60$) or if an autoencoder flags an outlier.
  * If true (or if the packet triggered a kernel drop), package the 32-dim feature vector into `CandidateVector` and stream it via `TelemetryService.StreamCandidateVectors`.

* **Collective Immunity Synchronizer ("Attacked Once, Immune Everywhere"):**
  * Open a persistent bidirectional gRPC stream to `IntelligenceService.SyncCollectiveImmunity`.
  * **Outbound:** When local modules (`04_ids_ips`, `05_waf`, `18_cps_sec`) drop an attacker, emit a `ThreatIndicator` upstream to Nexus.
  * **Inbound:** When Nexus pushes a `FleetDefenseRule`, immediately inject the target IP into the local kernel's `blocked_ip_map` via `libblackbox.so`.

* **Model OTA Listener & Shadow Execution:**
  * Query `ModelOtaService.PollTargetModel` periodically.
  * If a new model version is flagged:
    * Download the `.onnx` file from Nexus HTTP (`/models/<filename>`).
    * Verify the cryptographic SHA-256 against the response payload.
    * If `RolloutStage == STAGE_SHADOW_MODE`: Execute inference passively alongside the stable model (evaluate metrics, but do not drop packets).
    * If `RolloutStage == STAGE_FLEET_WIDE`: Trigger Sentinel’s internal zero-downtime hot-reload (`POST /api/v1/control/reload-model`).

### 2. `blackbox-essential` (Tier 2: Active Security & Kernel Mitigation Core)
*Provides the low-level kernel APIs and hardware identities consumed by Tier 3.*

* **Hardware Identity Serialization Helper:**
  * Expose clean C++ getters in `HardwareIdentity` (`get_machine_uuid()`, `get_tpm_quote()`, `get_backend_type()`) so `blackbox-sentinel` can populate the protobuf `HardwareIdentity` message without manual string parsing.

* **Thread-Safe eBPF Map Injection API:**
  * Ensure the BPF manager exposes explicit public methods:
    * `bool block_ip(uint32_t ipv4, uint64_t ttl_ns)`
    * `bool unblock_ip(uint32_t ipv4)`
  * This allows the Nexus collective defense thread in Tier 3 to insert broadcasted IP drops directly into `xdp_filter.o`’s kernel map within microseconds.

* **Atomic Telemetry Accessors:**
  * Expose real-time atomic performance counters:
    * `get_total_inspected_packets()`
    * `get_total_kernel_drops()`
    * `get_average_mitigation_latency_us()`
    * `get_ring_buffer_saturation_pct()`
  * These feed directly into Tier 3's heartbeat payload for Nexus SLA validation.

### 3. `xinfer-forge` (Tier 4: Continuous Active Learning Service)
*Integrates the training loop with Nexus's dataset curator and staging engine.*

* **Dataset Ingestion Adapter:**
  * Update the data loader in `forge/data/` to natively parse the curated dataset and manifest generated by Nexus (`/var/lib/sentinel-nexus/forge_datasets/forge_dataset_*.csv`).
  * Ensure feature columns ($f_0$ through $f_{31}$) map directly into the PyTorch Masked Autoencoder (MAE) and InfoNCE contrastive training pipelines.

* **Automated Nexus Model Staging Hook:**
  * At the end of `deploy/run_adaptation.sh` (after the model passes the `golden_attacks.yaml` safety gate and exports to ONNX Opset 17):
  * Compute the SHA-256 hash of `network_threat_vX.onnx`.
  * Send an HTTP `POST` request to `http://<nexus-ip>:9443/api/v1/ota/stage` containing the model name, hash, and download path.
  * This automatically transitions the candidate model into `SHADOW_MODE` inside Nexus without human intervention.

---

### 4. `xinfer-essential` (Tier 1: Universal AI Runtime)
*Ensures the inference engine can supply uncertainty metadata and run shadow models.*

* **Probability & Latent Embedding Export:**
  * Ensure inference results expose the raw softmax probabilities/logits alongside the classification label so Tier 3 can evaluate uncertainty metrics ($0.40 - 0.60$).

* **Dual-Model / Shadow Execution Handle:**
  * Ensure `IInferencePlugin` and `InferenceEngine` allow loading a secondary "shadow" model concurrently on the same device without memory collision or re-allocating backend contexts.

---

### 5. `sentinel-lab` (Tier 5: Academic Research Platform)
*Maintains academic purity, but gains benchmarking hooks to evaluate Nexus.*

* **Nexus Wire-Speed Benchmark Ingestor (Optional/Testbed):**
  * Add a CLI flag to `examples/run_full_evaluation.py` (e.g., `--stream-to-nexus`) that translates SLAB binary packets into `telemetry.proto` streams.
  * Allows university researchers to test and publish benchmark papers on Sentinel Nexus's central vector ingestion throughput using standard academic datasets (CIC-IDS-2017 / UNSW-NB15).

### Recommended Implementation Roadmap

1. **Phase 1: `blackbox-essential` (Tier 2)**  
   * Expose the TPM identity getters and atomic metric counters.
2. **Phase 2: `blackbox-sentinel` (Tier 3)**  
   * Build the `NexusUplink` gRPC background agent (Registration, Heartbeat, eBPF Drop Broadcast).
3. **Phase 3: `xinfer-forge` (Tier 4)**  
   * Connect the dataset loader to `/forge_datasets/` and add the post-training HTTP staging webhook.
4. **Phase 4: Full End-to-End Loop Validation**  
   * Edge detects anomaly $\rightarrow$ Streams vector to Nexus $\rightarrow$ Nexus curates batch $\rightarrow$ Forge retrains model $\rightarrow$ Nexus stages canary $\rightarrow$ Edge hot-reloads without downtime.
